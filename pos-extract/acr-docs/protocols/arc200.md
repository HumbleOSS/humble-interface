# ACR: ARC200 (protocol)

## Boundary

- **ARC200 contract interaction (approve, transfer, balanceOf, allowance, createBalanceBox, createAllowanceBox) MUST be performed through the token/contract module or wallet/transaction service.** UI must not construct ARC200 calls directly.
- **Reads (balanceOf, allowance, name, symbol, decimals, totalSupply)** should be exposed as queries via the token service or indexing layer.

## Allowed

- Using token service queries for balance and metadata.
- Passing token contractId and amounts to action builders that internally generate ARC200 approve/transfer/box creation as part of atomic groups.

## Forbidden

- Calling `arc200(contractId, algodClient, indexerClient).arc200_approve(...)` or similar from UI.
- Bypassing the ARC200↔ASA mapping when resolving token identifiers for display or for contract calls.

## Reference (source app)

- **ulujs arc200:** balanceOf, allowance, approve, transfer; createBalanceBox, createAllowanceBox used in pool/split flows.
- **Constants:** CONNECTOR_ALGO_ARC200 in constants/tokens.ts (ABI); pool spec includes arc200_approve, arc200_balanceOf, arc200_transfer, createBalanceBox, createAllowanceBox.
- **Approvals API:** REST `arc200/approvals?contractId=&owner=&spender=` for rewards (WAD).
